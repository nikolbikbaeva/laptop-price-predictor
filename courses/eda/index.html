Lesson 01 / Why explore first · 3 min

Look first.
Model later.

A file with 1,500 laptops is just rows and columns. Exploring it turns those numbers into questions you can actually answer.

Laptop prices

EDA = exploratory data analysis. You inspect, summarise and draw the data to learn what is in it, find problems, and form questions — before you build a model or make claims.

Work like an investigator.

You will loop back often

Exploring is not cleaning and not modeling. Cleaning changes data; modeling learns a rule to predict. Exploring comes first — and you return to it whenever something looks odd.

Before any calculation, find out what a single row describes and what each column really means.

Each kind of column asks a different question.

123

Numeric

Amounts you can measure or count: RAM, SSD size, weight, price. Ask: range, typical value, spread.

0/1

Binary

Yes or no, stored as 1 or 0: touch screen, dedicated GPU. Ask: what share is "yes"?

Abc

Text / category

Labels such as brand or CPU name. Ask: which values, how often? Models need them turned into numbers.

Meaning before math. HHD means hard-disk storage in GB. Price is the listed price; the source does not say which currency, so we treat it as USD. Check the column guide whenever a name is unclear.

Quick check / Read the meaning

The column Dedicated_Gpu only contains 0 and 1. What kind of column is it?

Exactly. An average of a binary column is a share: the mean of Dedicated_Gpu is the fraction of laptops with a graphics card.

Lesson 04 / Relationships · 4 min

How do specs
move with price?

Looking at two columns together is bivariate analysis. Does price change with memory? With a graphics card? With the brand?

Number × number → scatter plot

Look for direction, strength, clusters and odd points. The correlation between RAM and log(price) here is : a strong positive link.

Category × number → compare groups

Compare the median price per group, and always check how many laptops are in each group. A brand with 2 laptops says very little.

A pattern is a clue, not a cause. Laptops with 64 GB of RAM are often gaming or workstation machines with a strong GPU and a sharp screen. The chart alone can't tell you how much the RAM itself adds.

Lesson 05 / Data quality · 3 min

Trust, but check.

An odd value can be a typing error, a missing value in disguise, or a real but unusual laptop. Find out which before you change anything.

  1. Empty rows: 3.

    Three rows have no values at all. They describe no laptop, so they are removed.

  2. Impossible weights: 11 laptops weigh 0 kg.

    Zero is not a real weight; it means "unknown". We leave these laptops out instead of inventing a weight.

  3. No storage: 1 laptop with 0 GB.

    Every laptop has storage, so this is missing data too. Left out.

  4. Repeated models: models, rows.

    The same laptop appears with different RAM or SSD. That is not an error, but it makes a random test set easier — remember it when you evaluate a model.

  5. Currency: not labelled.

    The prices have no currency. We state our assumption (USD) instead of hiding it.

Keep a record. Write down each problem, the evidence, your decision and how many rows it affects. Keep the original file unchanged; do the cleaning in code (scripts/common.py) so anyone can repeat it.

Quick check / Missing or real?

A laptop has Weight_kg = 0. What is the best first step?

Yes. Zero is impossible here, so it is a missing value. Count it, decide, and write the decision down.

Your pocket checklist.

  • Write the question and what one row means.
  • Check column types, units and the column guide.
  • Look at distributions: center, spread, shape.
  • Compare groups and draw relationships — and count the group sizes.
  • Find impossible, missing and repeated values; document every decision.
  • Write notes that separate observation, limits and next steps.
